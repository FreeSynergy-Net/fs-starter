## 0.0.1

- First release: the host binary `fs-starter` (Linux and Windows x86_64, built by the CI from the tag) and the library `fs-starter`. The host opens the window of a program from its description (`fs-starter --description PATH`); sample data (`--sample-data`) shows it without a server. Parts not built yet (single instance, session, update, help, MCP) are named once on stderr. The release workflow `release.yml` calls fs-release v0.0.15; the workspace has `authors` (the release plan needs them for the package metadata). Version 0.0.0 -> 0.0.1.
- Auf Deutsch: Erste Veroeffentlichung: das Host-Binary `fs-starter` (Linux und Windows x86_64, von der CI aus dem Tag gebaut) und die Bibliothek `fs-starter`. Der Host oeffnet das Fenster eines Programms aus seiner Beschreibung (`fs-starter --description PFAD`); Beispieldaten (`--sample-data`) zeigen es ohne Server. Noch nicht gebaute Teile (Einzel-Instanz, Sitzung, Update, Hilfe, MCP) werden einmal auf stderr genannt. Der Release-Workflow `release.yml` ruft fs-release v0.0.15 auf; der Workspace hat `authors` (der Release-Plan braucht sie fuer die Paket-Metadaten). Version 0.0.0 -> 0.0.1.

- New crate `fs-starter-host` with the binary `fs-starter`: `fs-starter --description PATH` (or a bare PATH: a blueprint folder, a `forms/` folder or one file) opens the window of a program from its description without building the program. It uses `fs-forms-run` (git tag v0.0.5) as a library, so the words `--frontend`, `--style`, `--sample-data`, `--picture` are the ones of that crate; `--version`/`--help`/wrong words (exit 2) are the host's own, exit codes are those of `fs_starter::Exit`. The starter parts single instance, session, update, help and MCP are not built yet and are named once on stderr (`skeleton-part-pending`). Tests: CLI, element tree and picture tests of the real description of fs-tasks (copy in `tests/data/fs-tasks`).
- Auf Deutsch: Neues Crate `fs-starter-host` mit der Binary `fs-starter`: `fs-starter --description PFAD` (oder nur ein PFAD: Bauplan-Ordner, `forms/`-Ordner oder eine Datei) oeffnet das Fenster eines Programms aus seiner Beschreibung, ohne das Programm zu bauen. Es nutzt `fs-forms-run` (Git-Tag v0.0.5) als Bibliothek; `--version`/`--help`/falsche Woerter (Exit 2) sind die des Hosts, die Exit-Codes die von `fs_starter::Exit`. Die Starter-Teile Einzel-Instanz, Sitzung, Update, Hilfe und MCP sind noch nicht gebaut und werden einmal auf stderr genannt (`skeleton-part-pending`). Tests: CLI-, Elementbaum- und Bildtests der echten Beschreibung von fs-tasks (Kopie in `tests/data/fs-tasks`).

- The crate `fs-starter` moves in from the repo `fs-rpc` (`crates/fs-starter` with its 12 commits of history, as of fs-rpc v0.0.3). The dependency on `fs-rpc` becomes a git tag (v0.0.3), `Cargo.lock` is regenerated, `.fs-lock-sources.toml` (strict) is added. The code is unchanged; tests (all features) and clippy pedantic are green. Next: `fs-rpc` v0.0.4 without the crate; `fs-forms-bin` points at this repo.

# FreeSynergy starter

FreeSynergy starter: the host that starts a program from its blueprint package (`scaffold.toml` + `forms/` + texts) without compiling it. The host owns the parts that are the same in every program (session, update, appearance, help, the MCP switch, SCIM/OAuth); the modules are built once and run as services. Built with help from Claude (AI). Licensed under MIT OR Apache-2.0.

Status (0.0.3; 0.0.2 was never tagged, so the first host binary comes with 0.0.3): the library `crates/fs-starter` (words, server gate, frontend pick, exit codes) and the host binary `fs-starter` (`crates/fs-starter-host`). The host opens the window of a program from its description: `fs-starter --description PATH` (PATH is the data package `fs-blueprint new` wrote, a blueprint folder, a `forms/` folder or one file; a bare PATH works too: `fs-starter <package-path>`; the package line names program, skeleton and layout). The host builds the library `Parts` itself: the MCP switch is built and MCP is off (`fs-starter mcp --as ACTOR` ends with `mcp-disabled`, exit 1; the MCP entry itself is not built), and the start hooks run around the window. Single instance, session (the host does not call `resume_token` and `fresh` is always false, even with `--fresh`), update, help and the MCP entry are not built yet and are named once on stderr (`skeleton-part-pending`); where the host binds `fs-update` (update probation) is an open point (ADR 0105 open point 9), so the update hook is a no-op, named on stderr (`update-binding-pending`). Plan: ADR draft "Program without build".

## Auf Deutsch

FreeSynergy starter: der Host, der ein Programm aus seinem Bauplan-Paket (`scaffold.toml` + `forms/` + Texte) startet, ohne es zu kompilieren. Der Host haelt die Teile, die in jedem Programm gleich sind (Sitzung, Update, Darstellung, Hilfe, MCP-Schalter, SCIM/OAuth); die Module werden einmal gebaut und laufen als Dienste. Entstanden mit Hilfe von Claude (KI). Lizenz: MIT OR Apache-2.0.

Stand (0.0.3; 0.0.2 wurde nie getaggt, das erste Host-Binary kommt also mit 0.0.3): die Bibliothek `crates/fs-starter` (Woerter, Server-Tor, Frontend-Wahl, Exit-Codes) und das Host-Binary `fs-starter` (`crates/fs-starter-host`). Der Host oeffnet das Fenster eines Programms aus seiner Beschreibung: `fs-starter --description PFAD` (PFAD ist das Datenpaket, das `fs-blueprint new` schreibt, ein Bauplan-Ordner, ein `forms/`-Ordner oder eine Datei; ein blosser PFAD geht auch: `fs-starter <Paketpfad>`; die Paketzeile nennt Programm, Geruest und Layout). Der Host baut die `Parts` der Bibliothek selbst: der MCP-Schalter ist gebaut und MCP ist aus (`fs-starter mcp --as AKTEUR` endet mit `mcp-disabled`, Exit 1; der MCP-Eingang selbst ist nicht gebaut), und die Start-Haken laufen um das Fenster. Einzel-Instanz, Sitzung, Update, Hilfe und der MCP-Eingang sind noch nicht gebaut und werden einmal auf stderr genannt (`skeleton-part-pending`); wo der Host `fs-update` anbindet (Update-Bewaehrung), ist ein offener Punkt (ADR 0105 Offen 9), der Update-Haken ist daher leer und wird auf stderr genannt (`update-binding-pending`). Plan: ADR-Entwurf "Programm ohne Build".

Test note: the end-to-end test `what_fs_blueprint_new_writes_is_accepted_by_the_host` is `#[ignore]`d; run it with `FS_BLUEPRINT_BIN=<built fs-blueprint of fs-release main dcbf81b or newer> cargo test -p fs-starter-host -- --ignored`.
